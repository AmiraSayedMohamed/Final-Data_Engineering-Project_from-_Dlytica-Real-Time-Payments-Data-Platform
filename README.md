# Dlytica Capstone — Real-Time Payments Data Platform

This repository contains a production-like payments data pipeline implementing:

- Kafka (payments.raw, payments.deadletter)
- PySpark Structured Streaming (Bronze layer + deadletter routing)
- PySpark batch jobs (Bronze→Silver, Silver→Gold)
- Postgres data warehouse (Gold)
- dbt models and tests on Postgres
- Airflow DAGs to orchestrate hourly/daily pipelines
- A Python payments producer to simulate events

Run instructions (Windows PowerShell)

Quick commands (PowerShell)

# 1) Start the stack (uses .env at repo root)
docker compose --env-file .env up -d --build

# 2) Create host Ivy cache directory (one-time; speeds Spark startup by caching Maven jars)
New-Item -ItemType Directory -Force -Path $env:USERPROFILE\\.ivy2

# 3) Run streaming (one-off) — starts the streaming job inside spark container (writes Bronze parquet)
docker compose run --rm spark python /app/spark_stream/stream_payments.py

# 4) Run Bronze -> Silver (batch)
docker compose run --rm spark python /app/spark_batch/bronze_to_silver.py

# 5) Run Silver -> Gold (loads Silver into Postgres DW)
# Recommended: exec into running spark container so we reuse mounts and environment
docker compose exec spark sh -c "python -u /app/spark_batch/silver_to_gold.py"

# 6) Run unit tests (inside spark container; tests under `src/tests`)
docker compose run --rm spark sh -c "pip install --no-cache-dir pytest -q && PYTHONPATH=/app python -m pytest /app/tests -q"

Notes & troubleshooting
- If Spark downloads Maven artifacts repeatedly, mount your host Ivy cache (one-time) to speed subsequent runs; the compose file already mounts a named volume `ivy2` at `/root/.ivy2`.
- If a process appears to "hang" in your terminal, it may be running but silent; open a second terminal and check:
	- docker compose ps
	- docker compose logs spark --tail 200
	- docker compose logs postgres --tail 200


## Added scaffolding (dbt / Airflow DAGs / Reports)

I added a minimal dbt project under `src/dbt_project` with simple models that select from the Postgres tables produced by the pipeline and a `schema.yml` that defines dbt tests (not_null, unique, relationships, and a simple amount >= 0 check). Supply a valid `~/.dbt/profiles.yml` pointing to the `payments_dw` Postgres to run dbt in your environment.

Two demo Airflow DAGs were added to the repository `dags/` directory (the Compose file mounts `./dags` into Airflow):

- `dags/bronze_to_silver_dag.py` — hourly BashOperator that calls the Bronze→Silver script.
- `dags/daily_pipeline_dag.py` — daily BashOperators that call Silver→Gold, run dbt, and export reports.

Reports: `src/reports/generate_reports.py` exports two CSVs to `/data/reports`:

- `settlement_report.csv` (from `fact_settlement_daily`)
- `fraud_report.csv` (from `fact_fraud_signals`)

Docs: `docs/architecture.md` and `docs/runbook.md` were added with quickstart/run commands.

Note: a sample dbt `profiles.yml` is available at `src/dbt_project/profiles_example.yml` — copy it to `~/.dbt/profiles.yml` and edit credentials to run dbt locally or from the Airflow container.
